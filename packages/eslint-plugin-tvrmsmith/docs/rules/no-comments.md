# `tvrmsmith/no-comments`

Disallow code comments, except doc comments on declarations, comments a tool reads, and comments
in generated files.

**Guideline:** *Comments* — [`coding-standards/SKILL.md`](../../../../plugins/coding-standards/skills/coding-standards/SKILL.md#comments).
Code documents itself, and what another agent needs to know is written as a test. The C# half is
the `NoCommentsAnalyzer` Roslyn analyzer (TVRM0008); the Go half is the `tvrmsmith-no-comments`
golangci-lint module plugin in [`go/`](../../../../go/README.md). All three report the same
message and exempt the same four kinds of comment.

Severity in the preset: **warn**, like every custom rule here. The pre-commit lint blocks on any
warning touching a changed line (ADR 0010), so a new comment is still rejected.

## Why

The message is written for the coding agent that reads it:

> Remove this comment. Code should document itself: carry the meaning in a name, a type or an
> extracted function. A comment is often there to justify a workaround, and the fix for a
> workaround is the code. If another agent needs to know this, write a test that documents the
> behavior instead. Doc comments, suppressions, tool directives and generated files are exempt.

A comment that narrates the code duplicates it and rots beside it. A comment that justifies a
workaround is a sign the code is wrong. And a comment that records something the next agent must
know is the weakest place to keep it: nothing fails when it stops being true. A test named for the
behavior, asserting it, documents the same fact and breaks when the fact changes.

👎 Examples of **incorrect** code:

```ts
// The helper reads config before it is loaded, so the ceiling is inlined.
const RETRY_CEILING = 5

let attempts = 0 // reset on every request

// const legacyCeiling = 3
```

👍 Examples of **correct** code:

```ts
/** The retry ceiling for this client. Must stay under the gateway's own timeout. */
export const RETRY_CEILING = 5

// eslint-disable-next-line no-console -- the CLI's only output channel
console.log(RETRY_CEILING)
```

```ts
it('keeps the retry ceiling under the gateway timeout', () => {
  expect(RETRY_CEILING * BACKOFF_MS).toBeLessThan(GATEWAY_TIMEOUT_MS)
})
```

## What is exempt

Every comment is reported, own-line or trailing, `//` or `/* */`, prose, TODOs and commented-out
code alike, except these four kinds.

| Kind | TypeScript and JavaScript | C# | Go |
|---|---|---|---|
| Doc comment on a declaration | `/** ... */` (JSDoc, TSDoc) directly above a declaration, class or interface member, object property, enum member or import | `///` or `/** ... */` in the leading trivia of a type, member, accessor or local function | the comment group the parser attached to a declaration or the package clause, plus the trailing line comment on a struct field, `const` or `var` spec or type spec, which godoc renders |
| Suppression | `eslint-disable`, `eslint-disable-next-line`, `eslint-disable-line`, `eslint-enable`, `@ts-ignore`, `@ts-expect-error`, `@ts-nocheck`, `@ts-check` | `#pragma warning` is a directive, not a comment, and the reason on its line stays with it. `// ReSharper disable`, `// ReSharper restore`, `// NOSONAR` | `//nolint` and `//nolint:linter // reason`, `//lint:ignore`, `#nosec` |
| Tool directive | `/* eslint ... */`, `/* global ... */`, `/* exported ... */`, triple-slash `/// <reference ... />`, `istanbul`, `c8` and `v8` ignores, `prettier-ignore`, `/* @jsx... */` pragmas, `#__PURE__` annotations, a shebang | `// @formatter:off` and `// @formatter:on` | `//go:build`, `//go:generate`, `//go:embed` and every other `//name:arg` directive, `// +build`, `//line`, `//export`, `//extern` |
| Generated file | a comment above the first token holding `@generated`, `DO NOT EDIT`, `<auto-generated` or `auto-generated` | Roslyn's own generated-code detection: an `<auto-generated>` header, a `.g.cs` or `.designer.cs` name, or `generated_code = true` | the standard `// Code generated ... DO NOT EDIT.` header (`ast.IsGenerated`) |

A suppression's reason rides on the suppression itself (`-- reason` in ESLint, `// reason` after
`//nolint:` in Go, a trailing comment on a `#pragma` line in C#), so it is exempt with it.

### A doc comment has to document something

A doc comment is exempt only where it documents a declaration. `/** ... */` above an `if` or a
call, or `///` above a statement, documents nothing; it is prose in doc-comment delimiters, and
it is reported like any other comment. Without that check the exemption would be the easy way
around the rule.

Each language reads "documents a declaration" in its own way:

- **TypeScript and JavaScript.** The next token after the comment begins a declaration, counting
  a decorator as part of the class it decorates. A file overview (`@file`, `@module`) sits above
  the imports, so an import counts.
- **C#.** The comment is leading trivia of a declaration's first token, attribute lists included.
  A project that does not generate a documentation file parses with `DocumentationMode.None`,
  where the compiler hands `///` over as a plain comment, so the analyzer reads the delimiter off
  the text as well as the trivia kind.
- **Go.** Structural, as it is for `comment-block-length`. Prose immediately above a `var`,
  `const` or `type` inside a function body is that declaration's doc comment and is exempt.

### Not exempt

- **A licence header.** It is a comment nobody needs in the code, and the repository's licence
  file carries it. This is a choice, and the easiest one to revisit.
- **A line comment that happens to open with a directive's word.** ESLint reads `eslint`,
  `global` and `exported` only from block comments, so `// eslint complains here` is prose.
  `// go:generate` with a space is prose in Go for the same reason.

## Relationship to `comment-block-length`

`comment-block-length` is the older, looser half of the same guideline: it warns on a run of
non-doc comments over ten lines. A block it reports is almost always reported by this rule too,
one finding per comment. Both stay enabled for now. Doc comments remain exempt from both at any
length.

## Options

None. Every comment outside the exemptions is reported, so there is nothing to tune.

## No autofix

There cannot be one. Deleting the comment is the mechanical half; the rest, whether a better name,
an extracted function, a fixed workaround or a new test, is the author's judgement.
